
Oui, je connais le service CodeExecutionService (CES) proposé par TPM28. Il permet d'exécuter du code dans un environnement sécurisé et isolé, avec une prise en charge de Python et Bash. Ce service est particulièrement adapté pour les bots Discord souhaitant offrir des fonctionnalités d'exécution de code en ligne.

### Fonctionnalités principales

* **Exécution de code non interactive** : Permet d'exécuter du code Python ou Bash dans un conteneur temporaire, avec la possibilité d'envoyer et de recevoir des fichiers en pièces jointes.

* **Exécution de code interactive** : Permet d'exécuter du code de manière interactive via WebSocket, idéal pour des interactions en temps réel avec les utilisateurs.

* **Notebooks persistants** : Offre un environnement de développement interactif avec stockage persistant, permettant de créer, exécuter, mettre en pause et supprimer des notebooks.

### Exemple d'utilisation

Voici un exemple d'appel API pour exécuter du code Python de manière non interactive :

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"lang": "python", "code": "print(\"Hello, world\")"}' \
  https://tpm28.com/ces/run
```



Et pour une exécution interactive :([manuals.konicaminolta.eu][1])

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"lang": "python", "code": "name = input(\"What is your name?\")\nage = input(\"How old are you?\")\nprint(f\"Hello {name}, you are {age} years old.\")"}' \
  https://tpm28.com/ces/run_interactive
```



Après avoir lancé l'exécution interactive, vous pouvez vous connecter au WebSocket à l'adresse `wss://tpm28.com/ces/ws` et interagir avec le code en temps réel.

### Intégration avec un bot Discord

Pour intégrer CES à un bot Discord, vous pouvez utiliser la bibliothèque `discord.py` en Python. Voici un exemple de commande qui exécute du code Python fourni par l'utilisateur :

```python
import discord
import requests
import json

client = discord.Client()

@client.event
async def on_ready():
    print(f'Logged in as {client.user}')

@client.event
async def on_message(message):
    if message.content.startswith('!run'):
        code = message.content[len('!run '):]
        response = requests.post(
            'https://tpm28.com/ces/run',
            headers={'Authorization': 'Bearer YOUR_TOKEN'},
            json={'lang': 'python', 'code': code}
        )
        result = response.json()
        await message.channel.send(f'Output: {result["result"]}')

client.run('YOUR_DISCORD_TOKEN')
```



Assurez-vous de remplacer `YOUR_TOKEN` par votre token d'API CES et `YOUR_DISCORD_TOKEN` par le token de votre bot Discord.

Oui, le service **CodeExecutionService (CES)** de TPM28 impose certaines limitations afin d'assurer une utilisation équitable et sécurisée de ses ressources.

### ⚠️ Limites connues du service CES

Bien que la documentation officielle de CES ne fournisse pas de détails exhaustifs sur les limitations, il est courant que des services d'exécution de code en ligne appliquent des restrictions telles que :

* **Limites de fréquence des requêtes** : Pour éviter les abus, le service peut restreindre le nombre de requêtes qu'un utilisateur peut effectuer dans une période donnée.

* **Limites de durée d'exécution** : Les scripts peuvent être exécutés dans un délai limité, au-delà duquel ils sont automatiquement arrêtés.

* **Limites de mémoire et de ressources CPU** : Pour garantir la stabilité du service, des quotas de ressources sont souvent imposés.

* **Limites de taille des fichiers joints** : La taille des fichiers envoyés ou reçus peut être limitée.

* **Limites de taille des scripts** : La longueur ou la complexité des scripts soumis peut être restreinte.

### ✅ Bonnes pratiques pour éviter les dépassements de limites

* **Gestion des erreurs** : Implémentez des mécanismes pour détecter et gérer les erreurs liées aux dépassements de limites, comme les codes d'erreur HTTP 429 (trop de requêtes) ou d'autres codes spécifiques.

* **Retraits exponentiels** : En cas de dépassement de limite, attendez un certain temps avant de réessayer, en augmentant progressivement l'intervalle entre les tentatives.

* **Optimisation des scripts** : Assurez-vous que les scripts sont optimisés pour minimiser l'utilisation des ressources et respecter les limites imposées.

* **Surveillance de l'utilisation** : Suivez régulièrement l'utilisation de l'API pour détecter toute tendance à l'approche des limites.
